Task 1 — the plugin makes MemoryArena's memory better and cheaper

We registered CausalMemorySystem into MemoryArena at runtime (their repo stays byte-identical — it ships no licence, so we do not fork it) and ran it through their real HTTP memory interface on real travel episodes. Caveat stated up front: the graph used here is a rule graph read off the query, not a discovered one. This measures whether ancestor masking pays off; it does not yet exercise causal discovery.

How to read it: up is "the agent got the facts it needed", left is "we spent fewer tokens to give them". Our plugin sits up-and-left of the retrieval baseline — strictly better on both axes at once, which is the part that matters: it is not a trade, it is a dominance. Full-history is the information ceiling and we pay 2.0× less to sit -0.6 points below it.

What the ablation proves. causal-noG is our system with the causal graph switched off: same slot parsing, same hold rule, but it keeps every slot. It reaches 100% answerable — and costs 2487 tokens. So structuring memory is what preserves the facts, and the graph is what buys the compression: turning it on cuts 2487→1558 tokens (1.6×) for 0.0 points of recall. Neither piece alone does the job.

Task 2 — recovering the hidden driver of a published attack

Carrier: MINJA (NeurIPS 2025), a memory-injection attack. We reuse its released data and payload unmodified — the poison instructs the agent to shift its answer by +4 in ASCII when it sees the word "food", so an anomalous action is self-labelling (an answer in E–H). Our only additions are logging and a clean pre-injection probe phase.

Headline, stated plainly: half of the attack reproduced and half did not. The model obeys the poison rule when the instruction is in front of it (23/30 rounds). But the part that makes MINJA a memory attack — the record lying dormant and hijacking a later, clean query — did not happen even once: 0/8 on rounds where the poison was retrieved with no instruction visible, and 0/10 on the held-out test rounds.

How to read it: the anomaly tracks the visible instruction, not the memory. The bottom-right bar is the one that would have to be tall for the memory pathway to be real, and it is empty.

The confound that would have fooled us — and why this is the interesting part

Split the same data by trigger word instead of by visible instruction and you get a textbook gated read edge: pooled Δ = +0.69, and conditioned on the trigger, poison retrieval appears to drive the anomaly at Δ = +0.85 while being perfectly inert without it. That is exactly the signature the project predicts — and here it is an artifact.

The cause is mechanical: retrieval is edit-distance based, so a query carrying the long poison note is textually close to stored records that also carry notes. Poison therefore gets retrieved precisely on the rounds where the instruction is already in plain sight. The two variables are collinear, and any estimator that does not break them apart credits memory for what the note did.

The only statistic with discriminating power is the note-free ∧ poison-retrieved cell — and it is 0/8. The analysis code now refuses to report "driver recovered" without it.

auditwhat it can seeverdict on this data

That last row is a soundness result rather than the headline we were aiming for: asked to find a hidden memory driver, the method declined to invent one that was not there. Worth having — but it is not yet evidence that the method recovers hidden drivers, because this run contains none to recover.

Two candidate explanations, not yet separated

  • Retrieval. To sweep trigger rarity we drew benign filler from 40 MMLU subjects, which diluted memory so much the poison rarely won a top-3 slot — it was retrieved on only 8 of 66 note-free rounds. MINJA's own design keeps filler within one subject. A faithful same-subject rerun is in flight.
  • Model robustness. deepseek-v4-flash may simply not be steered by an instruction embedded in a retrieved exemplar.

The method itself: regime-conditioned discovery

Everything above uses a graph. This is the estimator that finds one when the edge is gated — switched on and off by a regime rather than always present.

A gated edge is multiplicative: the coefficient on the parent depends on the regime. Adding the regime as one more node — the standard move — only shifts the mean, so it cannot express that, and it fails. Conditioning on the regime recovers the edge:

sigma=0.00/20/22/2
sigma=0.010/20/22/2
sigma=0.10/20/22/2

Read edges recovered, out of 2. The middle column is the honest control: it is the obvious thing to try, it is what we shipped before, and it recovers nothing. Our estimator also flags each recovered edge as gated, which is what the defence below consumes.

Against the competitor: MemAudit

MemAudit (arXiv 2605.23723) is the nearest prior work and released no code, so we reimplemented both halves from the paper to make the comparison concrete.

MemAudit componentAUC precision@k
CMIS — per-record counterfactual influence 0.9620.889
Consistency graph — structural anomaly 0.3330.667

We do not beat it at detection, and should not claim to. CMIS ranks the poisoned records well. The difference is structural, not a score: MemAudit scores records one at a time against a static semantic graph, so it cannot say which earlier round's write drives a later action, and its graph cannot be handed back to the memory system as a selection policy. Our graph does both jobs — that dual use is the claim.

Substitution to disclose: their DeBERTa-v3 NLI relatedness is replaced by lexical overlap here, because this project is CPU-only. That mainly weakens their second row.

Closing the loop: gating the actions a driver would cause

An audit that only writes a report is not actionable. The same recovered structure is fed back so the memory system withholds the implicated record before the agent acts.

gateanomalous actions prevented collateral (benign rounds touched)
ancestry + regime (ours)23/23 (100%)10/73 (13.7%)
ancestry, no regime (ablation)23/23 (100%)26/73 (35.6%)
CMIS influence + regime16/23 (70%)0/73 (0.0%)

What the middle row buys. Dropping the regime condition turns the gate into a blocklist: it still prevents everything, but it withholds memory on more than twice as many healthy rounds. Requiring the regime to be open — the edge to be active — is what makes the defence cheap enough to leave switched on.

What we are not claiming

  • The graph in Task 1 is a rule graph, not a discovered one. It reads the person names out of the query. So this run demonstrates that slot-level ancestor masking pays off — it does not yet exercise GRACE or any causal discovery, which is the project's actual thesis. Wiring the learned graph in and re-measuring is the open work item.
  • Task 1's win is answerability at cost, measured on the memory context with no LLM in the loop (so it reproduces exactly). It is not an end-to-end task-success number; the travel agent runs up to 30 reasoning steps per round and at affordable episode counts that metric moves inside its own noise.
  • On travel the dependencies are named in the query, so discovery is unnecessary by construction here (a pre-registered test already concluded this). Discovery claims rest on the simulation track, not on this environment.
  • Task 2 did not demonstrate hidden-driver recovery, because on this model and configuration no hidden driver was operating. What it produced is a soundness check plus a documented confound.
  • The trigger-rarity sweep referenced in the working notes was run against an offline stand-in answerer, not a real LLM — it is a synthetic diagnostic, not a measurement.
  • MemAudit — the closest competitor — released no code, so "we beat it" is not demonstrated; only the two naive audits above were run.
