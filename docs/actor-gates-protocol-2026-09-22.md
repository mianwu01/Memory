# 顺序验收：Flash thinking actor 与真实记忆任务

本协议在本轮 API 调用前写定。用户要求继续长期主模型，因此请求
`deepseek-v4-flash`，不沿用最近诊断中的 Pro。不覆盖任何旧结果。

## 1. Actor 开发资格化

- 固定合成 HM3 Travel seed 80 / dev 前 10 个任务，各独立 3 次；不按结果
  替换任务。这不是重开原生 MemoryArena Travel，也不是新的结构实验。
- full HISTORY、完整 S0、v1/verbose，temperature 0，max_tokens 32768，
  `thinking: {type: enabled}`，不发送 `reasoning_effort: none`。
  保存请求/返回模型、推理内容存在性及长度、全部响应、usage、终止原因。
  先执行第一题第一次作为接口检查，成功返回后继续其余 29 次；不另加 smoke。
- 预定通过条件：30 个有效响应、至少 27/30 正确、至少 9/10 题 3/3 正确、
  无截断、每次有推理内容或明确非零 reasoning_tokens，返回模型均为同一个
  Flash 版本。分母固定；基础设施失败未解决即不能通过，不算算法答错。
- 单次 timeout 600 秒，SDK 不自动重试；每请求最多两次显式基础设施恢复，
  仅限网络、超时、408/429/5xx。成功返回的语义/格式错误从不重跑。
  记录在途请求，恢复前核对完整输入 hash。并发最多 3。
- 最多两版开发配置（各 30 个完整响应）：v1 thinking；若未通过，只允许
  一版基于开发失败归因的通用 prompt/执行说明修正。第二版启动前另写修正
  理由和完整 prompt；同模型、同题、同评分，不加入 gold、隐藏参数或
  自动推导的机制。全部开发版本都报告，不从重复中挑正确答案。
- 两版均未通过则暂停后续 discovery/测试调用，留下明确故障诊断；不无限
  调参。通过才冻结 actor。该门槛是工程筛选，不能当作泛化成功率的置信保证。
  新原生任务仍须使用自己的固定开发集重新资格化，HM3 通过不自动转移。

## 2. 原生任务与表示审查

只读审查可以与 actor 调用等待重叠；新场景实验须在资格化后开始。
选择公开具体仓库中有实际记忆写入、跨 session 读取与可独立核验结果的任务。
原生 Travel 已关闭，不重跑。记录 commit、数据切分、实际 agent memory
（与环境数据库区分）、write/hold/read 时间步、有效转移、变量维度、权限和
可调用的授权替代来源。逐项检查 query 是否直接给出所需依赖/答案、链接是否
直接给出结构、parser 是否求出了答案。样本太短、表示不稳定或 checker 只依赖
另一个 LLM 的场景不能直接宣布通过；不用合成加长充当真实轨迹。

## 3. 独立结构贡献

在研究对象合格、actor 在该任务合格后，先冻结小规模实验；discovered、
complete/no-discovery、三份固定错误结构、BM25、recency、随机选读采用同 reader、
同状态/动作接口、匹配输入预算。保存实际序列化与预算残差。若 discovered 和
complete 输入相同，停止该结构贡献主张。跨任务复用须明确训练与测试隔离，
训练 discovery / memory write / 推理 / 检索成本全计入，报告实际摊销点。
未满足前两关不执行大规模 discovery。

## 4. 同方法审计闭环

预先冻结案例并报告全部。独立检查 full 稳定正确、来源阻断、决策相关信息
替换、中性干预、真实授权工具替代以及无足够授权证据时的可执行拒答。
外部定义权限，不能从结构边推断恶意。干预必须改变决策相关量，不能仅平移
保持规则差值；授权替代必须真正查询独立来源，不能只改标签。
审计稳定性不合格不换案例制造成功。读依赖验证不冒充原始记忆时间结构。
