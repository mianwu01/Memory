# Actor 验收修正：模型 ID 的大小写

30 次请求完成后，初始 `report.json` 报 `passed=false`。任务数值为 29/30
正确、9/10 题 3/3、零截断、30/30 有推理内容；失败原因仅为返回 ID 集合中
同时出现 `DeepSeek-V4-Flash-0731` 和 `deepseek-v4-flash-0731`。

冻结协议要求“返回模型均为同一个 Flash 版本”；实现使用原始字符串集合长度，
把 ASCII 大小写差异当成版本变化。这是报告层的操作定义修正，**发生在看完
结果之后**，不追写为预注册规则。所有请求都仍请求 `deepseek-v4-flash`。

修正只对验收时的型号 ID 做 `casefold()`。保留所有原始 ID、原始严格判定
及其失败状态；版本数字/后缀、连字符、空格、型号名称等任何其他差异均不合并。
修正后的通过结论以这两种大小写表示同一型号/版本为前提，不声称核验了供应商
内部权重。`strict_literal_model_id_gate_passed` 与修正后的 `passed` 同时报出。

不修改原始 `actor_gate.py`、冻结协议、输入、响应或 `report.json`；只更新离线
验收报告。没有改 prompt、增加开发版本、替换 case 或重发任何 API 请求。
为这个元数据差异重跑 30 次并不能解决身份定义问题，也会重复已有实验。

回归验证：纯大小写差异允许合并；不同版本后缀、不同模型仍阻止通过。数值、
稳定性、thinking、完整性与截断门槛全部保持原值。
