## 1. shopping:history-borne 的是"状态值",不是"结构"

| 事实 | 数值 |
|---|---|
| 含全局预算声明的行 | **150/150**("All items combined must not exceed $X",X ∈ $60–$4340) |
| 任一步文本重述已花费/剩余预算 | **0/900**(选项列表连价格都没有——价格只在环境交互里) |
| k≥2 步声明"须与此前购得商品兼容" | 750/750 |
| 任一步文本告知"你此前买了什么" | **0/750** |
| 兼容性映射表(属性→属性)写在当步文本里 | 900/900 |

**读法**:依赖**结构**(链 step k ← k−1..1 + 预算超边)与映射表都在当步文本里
——按 C1 的结构判据,shopping 与原版 travel 同类(结构 query 可见)。
但进入映射表的**键**(此前实际购得商品的属性)与**预算状态**(累计花费)从不被重述,
只能从交互历史回忆。→ shopping 提供的是 **history-borne 状态追踪**,不是
**structure-learning**;它检验记忆的保持,不检验结构的发现。
(修正 t0-results §5 旧说法"预算是唯一 history-borne 机制":机制不止预算,
还有购得属性;但两者都是值追踪,不改变结构判定。)

## 2. math/phys:❗依赖大多是**隐式**的——此前的"点名引用"判断错了

| 量 | math | phys |
|---|---|---|
| 子任务问题数 | 354 | 86 |
| 含显式引用(\ref / Lemma N 等) | **26(7.3%)** | **18(20.9%)** |
| k≥2 子任务 background 为空 | 68% | 77% |
| \ref 解析:同步 background 内(=query 时可得) | **0/28** | 7/35(全是子任务 1) |
| \ref 解析:落在**历史**子任务 | 12/28 | 23/35 |
| \ref 悬空(全行都无定义) | 16/28 | 5/35 |

**关键样例**(phys row 0 sub 2,全句 69 字符,零表面标记):
> "For $\mathcal{A}=\{1,3\}$ with $\sigma=4$, determine $(c_2,c_3,c_0)$."
`\mathcal{A}, σ, c_i` 与全部确定方程只存在于子任务 1——**无任何词法标记的省略式
历史依赖**。同型:未在本地定义的宏(`\cin`, `\Zc`)、"the method above"。

**修正 t0-results §5 旧说法**("math 的 Lemma N.M 引用同样是点名"):
点名引用只占 7–21%,且 k≥2 的引用**无一**在当步 background 中重述;
**79–93% 的子任务问题没有显式引用,其中包含无标记的隐式历史依赖**。
→ **math/phys 是 MemoryArena 中唯一 as-is 接近满足 C1 的环境**。
