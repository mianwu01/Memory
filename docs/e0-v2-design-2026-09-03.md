# E0 v2 design — recovering edge identity and activation regime in a small memory system (frozen 2026-09-03)

Written before the confirmatory seeds ran. Development used seed 99 only; seeds 0–4 are
confirmatory and were not looked at while the design or any hyperparameter was open.
Code: `code/e0v2/`. Results land in `results/e0v2/`. CPU only.

## 1. Why v0/v1 could not carry the claim

The earlier E0 (`code/e0_synth.py`, `code/regime_grace.py`) supported "regime conditioning
recovers the gated read edge", but three parts of its code leaked the answer into the method:

1. The regime label of a learned edge was assigned after the fact from the target name
   (`d == 1 -> write/hold`, `d == 2 -> read`). Gate localisation was hard-coded.
2. Each regime was regressed only on the target it was supposed to explain
   (`("write", [1]), ("read", [2])`). Target knowledge was an oracle input.
3. Every episode wrote at t = 5 and read at t = 5 + Δ, so timestep position predicted the regime.

Two further weaknesses: the read edge was contemporaneous (m_t → y_t), which invites a
debate about lag-0 orientation that has nothing to do with gating; and the SCM had one
scalar memory, so a reviewer can call it a switching-regression toy.

## 2. The v2 SCM

32 observed variables (n = 12 + 20 distractors; n_dist is a parameter):

| block | variables | mechanism |
|---|---|---|
| cues | c1..c4 | fresh N(0,1) every step |
| memory slots | m1..m4 | written, held, or reset, see regimes |
| readouts | y1, y2 | read under a read regime, otherwise N(0,1) |
| query context | q1, q2 | fresh N(0,1) every step; enter the readout at read time |
| distractors | d1..d20 | VAR(1): self 0.5, d_{2k} → d_{2k−1} 0.3, noise 0.5; regime-free |

Observed regime u_t ∈ {idle, write_A, write_B, hold, read_A, read_B}. All cross-variable
mechanisms are lag 1:

| regime | active mechanisms |
|---|---|
| idle | every slot reset to N(0,1) (expiry); readouts noise |
| write_A | m1 ← c1(t−1), m2 ← c2(t−1) (+0.05 ε); slots 3,4 hold |
| write_B | m3 ← c3(t−1), m4 ← c4(t−1); slots 1,2 hold |
| hold | m_i ← m_i(t−1) + σ_hold ε, all slots |
| read_A | y1 ← 1.0 m1 + 0.8 m3 + 0.5 q1 (all at t−1) + 0.1 ε; all slots hold |
| read_B | y2 ← 0.8 m2 + 1.0 m4 + 0.5 q2 (all at t−1) + 0.1 ε; all slots hold |

Ground truth is the table coef[i, j, lag=1, u] = a_ij · g_ij(u): 44 edges (4 write, 4 hold,
6 read, 30 distractor) and 206 edge × regime cells. The same candidate edge m1 → y1 has
coefficient 0 in five regimes and 1.0 in read_A; m1 → m1 is 1.0 in four regimes and 0 in
write_A and idle. That table, with the regime axis, is the object every arm is scored on.

Schedule per episode (all random): idle prefix U[1,3]; a write of random type; with
probability 0.5 a second write after U[1,8] hold steps (an overwrite when the type repeats);
hold U[3,15]; a read of random type; with probability 0.3 a second read after U[1,8] hold
steps. A read of type B after only a write of type A reads unwritten slots. Episodes are
concatenated into one series of T steps. At T = 10,000 this gives about 580 episodes and
reads on 7% of steps (3.5% per read type).

`mechanism="mlp"` replaces the write and read maps by fixed random tanh networks (8 hidden
units, unit output scale) with the same parent sets; hold stays the identity. The gate table
is then binary and coefficient error is undefined.

## 3. Arms

| arm | sees u | output | notes |
|---|---|---|---|
| pooled_ridge | no | G | OLS of every x_j(t) on x(t−1), BH-FDR α = 0.01 |
| additive_u | as a node | G | pooled OLS + one-hot(u_t); u can only shift the mean |
| interaction_u | yes | G(u) | one slope per regime in one joint OLS, pooled residual variance |
| interaction_u_hc | yes | G(u) | same with White HC0 sandwich standard errors |
| per_regime | yes | G(u) | OLS inside each regime, every target, global BH-FDR; the v0 estimator with the oracle removed |
| pcmci | no | G | tigramite PCMCI, ParCorr, τ = 1, BH q < 0.01 |
| grace_official | no | G | causalts `run_cdnots_gated`: CDNOTS skeleton + Hard Concrete L0 gates |
| gates_pooled | no | G | our re-implementation of GRACE's gate (one z_e per edge) |
| grace_per_regime | yes | G_u | gates_pooled fitted on each regime's rows separately |
| **regime_grace** | yes | G(u) | one model, one Hard Concrete gate z_e(u) per edge × regime, regime-specific coefficient, learned σ_j(u); L0 on every gate |
| regime_grace_shared | yes | G(u) | ablation: gate logit a_e + b_{e,u} with a shared edge term |
| regime_grace_screen_pooled | yes | G(u) | ablation: candidates restricted to a pooled lenient screen (α = 0.1) |
| regime_grace_screen_union | yes | G(u) | ablation: candidates = pooled ∪ per-regime lenient screen |
| \*@shuffle | permuted u | G(u) | negative control: u_t → π(u_t), for per_regime, interaction_u_hc, regime_grace |

Pooled arms report a single graph; the only reading a regime-free graph admits is "active in
every regime", and that is how their cell scores are computed. Regime label of an edge in
every regime-aware arm is the set of regimes where its test passes or its gate is open;
no arm receives target or regime hints.

Hard Concrete constants (temperature 2/3, stretch [−0.1, 1.1], init −0.5), the differentiable
L0 term and the closed-form λ (GRACE Eq. 11) are copied from causalts. Development finding
that fixed the model: a coefficient shared across regimes is pinned to zero by the
near-deterministic hold rows (learned σ ≈ 0.01 gives precision weights around 10⁴), so gates
that should open in write or read regimes never do. Coefficients are therefore regime-specific
and sharing lives only in the gate logit (the `_shared` ablation) or in the candidate screen.

Frozen training settings: Adam lr 0.01, batch 256, at most 150 epochs, early stop on the
training loss with patience 20, gate threshold 0.5, λ = 0.5 × formula (selected on seed 99 by
held-out likelihood over scales {0.125, 0.25, 0.5, 1, 2}; scales 1 and 2 close weak
distractor gates in rare regimes, scale 0.125 admits false cells). After selection every
arm's coefficients are re-estimated by OLS on its selected parents (pooled arms on all rows,
regime-aware arms inside each regime); this relaxed estimate is what the coefficient metric
and the heatmap use.

## 4. Metrics

1. Edge existence: P/R/F1 over (i, j, lag).
2. Gate localisation (primary): P/R/F1 over (i, j, lag, u) cells. `cell_mem` restricts the
   universe to targets in {m1..m4, y1, y2}, because the 180 always-on distractor cells would
   otherwise dominate; `gate_exact` is the fraction of the 14 memory edges whose full on/off
   vector over the six regimes is reproduced exactly.
3. Coefficient recovery: mean |β̂_ij(u) − β_ij(u)| over true cells (linear SCMs), plus the
   truth-versus-estimate heatmap over the 14 memory edges × 6 regimes.

Typed recalls (write / hold / read / distractor) are reported at both levels.

## 5. Experiments and frozen judgements

**E0a — identification.** n = 32, T = 10,000, σ_hold ∈ {0, 0.01, 0.1}, seeds 0–4, every arm.
- C1 (gate recovery): regime_grace reaches cell_mem F1 ≥ 0.90 in at least 4 of 5 seeds at
  every σ.
- C2 (model class): no pooled arm (pooled_ridge, additive_u, pcmci, grace_official,
  gates_pooled) reaches cell_mem F1 ≥ 0.90 in any seed, whatever its edge F1.
- C3 (negative control): every @shuffle arm has cell_mem F1 < 0.70 and gate_exact < 0.50
  in every seed.
- C4 (honest baseline): if interaction_u_hc or per_regime also satisfies C1, the paper claim
  is "the regime-indexed table is the right estimand and several estimators can fit it";
  Regime-GRACE is then the estimator that extends GRACE's object, and no superiority over the
  linear regime-aware arms is claimed.
E0a passes when C1, C2 and C3 all hold. A λ-sensitivity row (scales 0.25 and 1.0) and a
max_lag = 2 row (pooled_ridge, per_regime, regime_grace) are reported as secondary.

**E0b — rarity.** Presets with read fractions near 20%, 10%, 5%, 2%, 1% (realised values are
recorded), T ∈ {1k, 2k, 5k, 10k, 20k, 50k}, seeds 0–4, σ = 0.01; arms pooled_ridge,
interaction_u_hc, per_regime, gates_pooled, regime_grace. Reported: the smallest T at which
the median cell_mem F1 over seeds is ≥ 0.90, per arm × preset; and read-cell recall curves.
Descriptive, no pass/fail.

**E0c — scale and nonlinearity.** Linear: d ∈ {50, 200, 1000}, T = 10,000, σ = 0.01,
seeds 0–2, arms pooled_ridge, interaction_u, per_regime, gates_pooled, regime_grace.
MLP mechanisms at d = 32, seeds 0–4, adding gates_pooled_mlp and regime_grace_mlp. Descriptive;
the expected failure modes (per-regime OLS underdetermined when a regime has fewer rows than
candidates, linear arms missing MLP write edges) are recorded as they occur.

## 6. Environment

CPU only: `CUDA_VISIBLE_DEVICES=""` is set before torch is imported and workers use 2 torch
threads each. tigramite 5.2.10.1 and causalts 0.26.0 (with causal-learn, dcor, statsmodels,
patsy, numba, llvmlite, pytorch-lightning, pydot, momentchi2, array_api_compat) were
installed with `pip install --no-deps --target <dir>` outside the shared site-packages and
are reached through `E0V2_PYLIB=<dir>`. Torch's inductor cache directory is redirected to
`.tmp/torchinductor` because the platform default is unwritable.

```bash
export E0V2_PYLIB=<pip --target dir>
python3 code/e0v2/run.py --exp e0a --seeds 0 1 2 3 4 --workers 5 --lambda_scale 0.5
python3 code/e0v2/run.py --exp e0a --seeds 0 1 2 3 4 --arms regime_grace --lambda_scale 0.25 --tag _lam025
python3 code/e0v2/run.py --exp e0a --seeds 0 1 2 3 4 --arms regime_grace --lambda_scale 1.0 --tag _lam100
```
