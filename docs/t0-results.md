## 1. M1/M3:召回轴按预注册预期塌缩 ✅(预期得到证实)

**每一条依赖的直接父辈都在 query 字面上点名。** 不存在无名指涉
(代词 "hers/it" 均为句内回指,同句必有姓名);不存在需要未点名 round 的约束。
且来源**单元格**也基本显式:possessive 句式 100% 点名槽位、95.6% 点名日期
(4,120/4,311;其余 191 句省略日期);join / elided 句式的来源单元格 = 目标单元格,同样可从字面推出。

→ **round 级召回不需要图**:一个姓名解析器即是 oracle。与 LongMemEval 的
`E(q) ≈ An_G(Y_q)` 同构,预注册预期(§8 "预期直接父辈基本都被点名")成立。

## 2. 但与 LongMemEval 不同:三个有空间的轴

### 2a. 基准默认检索器有真实缺口(precision/coverage 轴)

对每个含依赖的 round,用与基准同规格的 BM25(query 原文 → 已有块,top_k=3 为 `rag.py` 默认):

| k | 父辈全覆盖率 | 父辈召回 |
|---|---|---|
| 1 | 24.7% | 48.4% |
| 2 | 42.1% | 71.6% |
| **3(默认)** | **75.1%** | 89.2% |
| 5 | 97.5% | 99.0% |

**默认配置下 24.9% 的依赖 round 至少缺一个父辈块。** 而全 query 姓名匹配召回 1.0
但精度 0.49(preamble 把所有前人都点名,平均拉回 4.6 块)——去掉 preamble 的
约束句姓名匹配达到召回 1.0 / 精度 1.0 / 平均 2.07 块,但**此数对本解析产出的 gold
是套套逻辑**(gold 本身来自姓名解析),只能读作"姓名解析器即 oracle"的另一种表述。

### 2b. 单元格级结构远非平凡(结构轴)

- **45.6% 的被引用单元格自身也是被约束的目标**(3,025/6,635)——单元格级因果链真实存在
  (Bart←Emma←Eric 型),不是一步依赖的堆叠;
- round 级链深:**270 个 episode 全部 ≥4**(分布 4:77, 5:96, 6:77, 7:20);
- 类型级图非对角:possessive 边中 **38.8% 跨槽位**(dinner→breakfast 等)、**81.4% 跨日期**;
  accommodation→accommodation 最重(1,780),餐饮槽两两间均有数百条。

### 2c. 压缩空间巨大(压缩轴,承 LongMemEval 结论)

以字符数计(≈token×4;块 = query + 最终行程,**尚不含** 30 步 scratchpad):

| 保留内容 | 平均字符 | 占全量记忆 |
|---|---|---|
| 全部已有块 | 12,605 | 100% |
| BM25 top-3 | 8,146 | 64.6% |
| gold 父辈整块 | 6,224 | 49.4% |
| **所需单元格值** | **290** | **2.3%** |

**单元格级抽取比整块检索省 30–45×。** 真实运行时块含 scratchpad,分母只会更大——
此比例是压缩空间的**保守下界**;同理 BM25 的上表成绩是**乐观上界**(真实块噪声更多)。

## 3. 判据裁决

### 3.0 ❌ 初版裁决已作废(同日修订)

本文档初版曾写"部分通过:进 v1 集成",依据是 BM25@3 缺 25%。**该裁决误用了预注册判据。**
判据原文的第 (4) 条问的是"**名字检索**有无系统性精度缺口",不是"BM25 有无缺口"——
BM25 弱只说明 BM25 弱;而 T0 自己证明了 query-aware 解析器就是 oracle(§1)。
按判据第二分支——"(3) 空且 (4) 干净 → 召回轴重演 LongMemEval"——**触发的是第二分支**。

### 3.1 修订后裁决:travel 原样(as-is)不能作为因果记忆的主基准

三条理由,全部由 T0 数据**解析地**给出,无需再跑对照实验:

1. **实例 DAG 是当前 query 文本的确定函数**(6,826/6,829 句可解析,来源单元格显式)。
   依赖不需要从历史中"发现"——它在当前输入的表面被完整重述。时序因果发现的存在理由
   ("在无人告知时推断哪些过去重要")在此**按构造不成立**。
2. **压缩收益属于结构化表示,不属于因果发现**:单元格抽取只需解析(知道要哪个单元格),
   不需要学得的时间图。30–45× 是 structured-memory 的论据,不是 causal-memory 的论据。
3. **链与跨槽边只说明"数据里有图",不说明"图需要被学习"**:图是逐实例文本标注的,
   不是须由跨期统计依赖推断的潜结构;且类型级图的形状反映的是模板生成器的采样先验,
   学它 ≠ 学一个 agent 世界的因果机制。

GPT 建议的三项 go/no-go(parser vs oracle 图 vs 学得图;跨 episode 共享机制;
图干预的超额收益)中,第 1、3 项已被上述第 1 条解析地回答(parser ≡ oracle,
干预无法超过重构了全图的解析器);第 2 项同样按构造成立——本环境没有随时间演化的
潜机制,round t 的依赖与 query 同时到达。**跑这三个实验是多余的仪式,结论已定:no-go。**

### 3.2 travel 保留的三个次要角色

1. **集成 harness**:两方法接口、`MEMORY_FACTORIES` 注册路径依然是最低成本的实机管道;
2. **structured-memory / 压缩测试台**(§2c)——但这是**另一个研究问题**,不得混称因果记忆;
3. **重构原料**:全部 6,826 条解析边在手,可程序化地把依赖声明从当前 query
   **移出/去名化**(见 §5),构造出依赖真正住在历史里的 "travel-R"。

## 4. 限制

1. gold 来自本解析器:解析覆盖 6,826/6,829,但 gold 与姓名匹配检索存在共构,
   相关指标(§2a namecons)不作证据使用;
2. 块无 scratchpad(未运行 episode):BM25 成绩偏乐观、压缩比偏保守,方向已标明;
3. 单元格链(2b)按 (day,slot) 粗配:elided 句式的日期按目标日期填充(223 句,3.3%),
   可能少量高估或低估链率;
4. 本测只覆盖 travel;shopping 的链结构(固定 6 步兼容链)未测。

## 5. 下一步(修订版)

**停止 GRACE 集成**(本就未开始)。基准适格性标准(T0 教训的一般化,写进 v0.2):

> **C1(无 query 时 oracle)**:依赖结构必须住在过程里,而非当前输入的表面文本——
> 任何只读当前 query 的解析器/检索器在同预算下不得重构实例依赖;
> **C2**:重复轨迹 + 跨轨迹共享(或可条件化)的机制,使结构可从数据统计地学出;
> **C3**:图的正确性可对 ground truth 验证;
> **C4**:图对下游有超出最强非因果基线(matched budget)的增益空间。

三条平行路径,下次会前给 Yujia 摆出:

1. **E0 合成实验**(formulation.tex §exp 已设计,7 月会 Yujia 已支持):
   write–hold–read SCM,依赖真正潜在于过程,C1–C4 全满足;这是唯一无需新设计即可开跑的路径。
2. **travel-R 重构**:利用 T0 的全量解析,把依赖声明从消费方 query 移到**来源轮**
   (前瞻式:"Bart 之后会跟我住同一家")或去名化("跟订了海鲜餐厅的那位一致"),
   并加保留预算——依赖被迫从历史轨迹中追踪。设计空间需与 Yujia 对齐后再做。
3. **按 C1–C4 重审既有候选**:~~初步猜测(math 引用=点名;shopping 预算是唯一
   history-borne 机制)~~ **已被 2026-08-20 全量普查推翻/修正,见
   `benchmark-audit-c1c4.md`**:math/phys 的依赖 79–93% 是**隐式**的
   (无标记省略式引用,k≥2 的 background 大多为空)→ **as-is 最接近 C1 的真实环境,升格**;
   shopping 是 history-borne 的**状态追踪**(购得属性 + 累计花费从不被重述)
   但结构仍在 query 文本中 → 佐证用。三路径执行结果:E0 已跑(`e0-v0-results.md`),
   travel-R 已建成并审计(`travel-r-v0.md`),普查完成(`benchmark-audit-c1c4.md`)。

汇报框架:T0 是一次**成功的表述压力测试**——它按预注册判据淘汰了候选基准,
